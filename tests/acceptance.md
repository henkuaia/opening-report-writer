# 优化验收标准

这是项目迭代的验收约定，不是效果认证。每轮先定位1—3个具体使用问题，再修改和检查受影响场景；最多三轮，未解决项保留，不以改写篇幅或规则数量衡量成熟度。

## 怎么验收

| 项目 | 通过条件 | 对应输入 |
| --- | --- | --- |
| 能上手 | 内层安装目录、首次请求与后续补材料方式明确；已知同名位置已检查，不自动覆盖 | README；T9 |
| 能拆题 | 对象、问题、约束及验证对应具体题目；未知信息不转成事实 | T1、T7、T9、T10、T11、T15 |
| 能组织论证 | 连续正文有共同问题、机制关系与匹配来源；关键判断可从正文定位，不依赖对话补全；补强能说明基线作用、拟改变的环节、资源前提及关键对照排除的解释，不以指导句或风险提示代替正文；仅用于规避争议或汇报修改过程、对论证无贡献的句子被删除，会改变结论适用范围的限定与协议设计理由仍被保留；方案说明观测如何支持或削弱假设、判断是否达标，冲突及条件不被抹平 | T2、T8、T13、T16、T17、T19、T20、T23、T24 |
| 能正确修改 | 正确内容、参数、限定及原引用保留；反馈转成有依据的局部修改；默认篇幅与可选结构示例不造成删减指定内容或强制改写工作项数量与前期基础规模；过程说明移出后仍保留研究限定与协议理由；移出信息有去向，候选状态在授权位置一致，既定多折评价协议不被默默降为单折，未授权章节不变 | T3、T5、T8、T12、T14、T16、T17、T18、T19、T20、T23、T24 |
| 不编造、不越界 | 不造文献、数据、成果或身份；只读阶段不改报告；私人材料不进入公开包 | 全部 |
| 占位符与防编造 | 定性描述不脑补为具体数值，不捏造题录或未给案例细节，不将自设配置挂在原引文下；缺失材料按唯一全角格式 `【待补：<数据/文献/基本情况之一>｜具体缺什么】`（如 `【待补：数据｜样本量与划分比例】`）显式占位（不与 `[n]` 引文编号冲突），Word草稿高亮且定稿前清零，正文外附待补清单 | T25a；[占位符与图稿结构脚本](check_placeholder_and_assets.py) |
| 标点与句式边界 | 研究内容、实验组、指标、协议步骤、创新点等真并列对象允许统一模板和序数列项，仅论述性段落避免机械序数排比；名词性术语（如“系统”）与紧跟实质结论的“综上所述”保留；同一句小括号不超过1处，缩写、单位与量纲、编号、取值范围、符号定义与分组代号括号保留，括号内必要限定条件保留并融入主句；被提及的词/标签值/字段名/问卷题项引号保留，“黑盒”等标准技术术语不加引号但不强改，只清理比喻性黑话 | T25b、T25c |
| 图配色与源码 | 学校模板、导师/用户要求及灰度打印要求优先；无限制时采用4—5色以内、承载输入/处理/输出/评估等学科中性语义且灰度可辨的配色；源文件与渲染图同目录同名且节点/流向一致，缺渲染环境时只算草稿并如实披露 | T25d、T25e；[占位符与图稿结构脚本](check_placeholder_and_assets.py) |
| 能诚实交付 | 分开记录文字、文件生成、解析、渲染查看和实际软件打开 | T6 |
| 无明显回归 | 模板按职责映射；原任务入口、章节职责及内部链接仍有效 | T4、T7及结构检查 |
| 改动有价值 | 每项改动对应已发现问题，并有受影响任务产物和判定依据 | 本轮检查记录 |

“不编造、不越界”和重要信息完整性是必须满足项，不能用平均分抵消。状态只用通过、部分通过、未通过；工具受阻说明原因，但不计为通过。

## 复测方法

1. 从 [基础输入](inputs.md) 或 [公开证据与成稿输入](public-writing-inputs.md) 选择受影响任务。执行者先读待测公开副本规则和输入，生成实际答复或文件，再看历史输出；不复制历史答案冒充新运行。
2. 按输入要求处理读写范围。仅诊断时不改报告；明确授权后才交付新版。检查前后内容及重要限定，不以“文件可解析”代替语义判断。
3. 用上表判定，记录输入编号、实际输出、依据和未完成项。会话内生成/自评如实标为自测；结构脚本仅证明其检查过的结构，不能证明写作能力。
4. 输入、规则和环境未受影响时复用已有结果，不重复运行全部任务。失败先判断共同原因，只修复相关规则，再复测受影响项。

判断写作质量时，将一个关键主张对应到输入依据和正文位置，并说明它为何回答了用户的问题；不能只检查引用、指标或关键词是否出现。目标达标与结果改善分开判定。未授权部分的完整性优先比较实际输入和交付文件，不以“已保留”的自述代替检查。判定条件在生成前明确，不把本次答案反写成唯一标准措辞。

## 成熟度边界

指定范文的文末排版另按 [F10—F11](citation-format-check.md#f10f11-指定范文的文末排版)检查：先比较真实文件和显示，再局部修改；默认体例不覆盖指定参照，字段省略须符合来源身份及授权，不能改动正文/编号。格式一致、内容核验与跨软件效果分开判定；虚构小样不替代真实用户效果验证。

[参考论文到图文分轮自测](reference-workflow-check.md)检查主动选文、确认前后、范例迁移及局部任务边界。完整报告的新流程须分别满足：候选有核实来源、适配理由和全文状态；确认前不提前仿写完整稿；确认后正文用出论证方法且无图可读；图文阶段不改变已确认事实。模拟确认、文字自测、真实绘图和Word实测分开记录，未执行不计通过。

[参考文献格式与编号专项自测](citation-format-check.md)记录组合编号、非引用数字保护、模板冲突及版本缺字段处理，并补测本地材料排除、获准预实验的限定和正式版本取舍。旧测试中的内部题录准入结论已标为失效，不能沿用其整体通过判断。须检查正文、表格、题注及图内文字，不以只删文末条目代替处理；不替代Word排版或独立评测。

该记录的F6—F9增加主张与多篇引用专项：共同支撑允许合引，分别支撑就近对应；只有格式授权时不擅自重写或删来源。按“支持关系、展开来源集合、Word实际效果”分别验收，缺原文不妨碍确定的格式修正，但不能宣称依据已核实；单篇样例不能推出组合规范。Word检查涵盖域更新后的上标、标点及非引用对象保护，不能只查缓存属性。可用 [小样脚本](check_citation_word.py)重建人工选区的结构测试，不将其当成自动识别或内容核验工具。

目前记录包括 [第一轮自测](session-check.md)、[后续文字自测](followup-check.md) 和 [请求类型与引用读取自测](task-routing-check.md)，不包含独立评测或真实学生效果验证。早期T6只有Word生成与解析；2026-11-04的F9另完成了1页引文小样的实际Word打开、域更新、导出及查看，但捆绑渲染器的域上标仍未通过。F9不替代完整报告或其他Word能力的验收。跨客户端与跨学科能力未验证，不能据上述小样称全面成熟。

[公开证据与成稿自测](public-writing-check.md)另外记录了官方Skill借鉴来源和T13—T15的实际产物。公开原文核对、产物可解析、同会话读者检查和独立使用效果是不同证据层级，不因增加来源或缩短入口就推断效果已经提升。

如需提高证据等级，下一步应在得到授权后用未参与改写的测试者或真实新用户复测，而不是继续累加规则；额外模型调用、资源和发布均需相应授权。
