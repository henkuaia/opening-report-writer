# 章节与段落怎么写

本指南提供可调整的章节职责与论证方法；1.2的虚构教学案例见按需读取的案例文件，真实论文的写法分析需另读原文。这些是写作建议，不是学校标准、固定段落数或字数。按资料密度调整，正式正文使用连贯段落，规划时才用表。

下列编号仅对应默认骨架。使用其他模板时按职责理解并替换所有目标位置，包括正文交叉引用及移位建议；模板没有独立的“难点”或“预期目标”节时，将相应论证写入允许承载它的栏目，不强加章节编号。

## 组织主线的选择

根据研究问题选择按条件差异、约束递进或处理层级组织工作项。条件差异需说明各条件对应什么难点；约束递进需说明前后依赖；处理层级需说明各环节如何共同服务一个目标。它们是可选组织方式，不规定工作项数量，也不构成创新依据。研究方案先解释方法，再给必要的图、公式与验证设计；已有结果另作可行性材料，不以结构图代替论证。

## 1.1 论文选题的意义

- 回答：为什么此对象/任务值得研究，具体困难是什么，成功会在什么边界内有价值？
- 输入：真实应用需求、任务定义、有来源的背景事实、拟解决瓶颈。
- 段落顺序：应用或科学背景 → 现有流程与限制 → 限制如何影响目标 → 本课题切入点 → 受约束的意义。通常几段足够，不先写长篇技术史。
- 图表：只有解释任务确有帮助时用对象示意或流程图；来源和用途清楚。
- 连接：末段引出1.2要比较的技术路线，不提前宣称本方法获胜。
- 常见错：大行业铺垫不落题；给未经核实的疾病比例；技术精度直接推断患者获益。
- 验收：删掉题目后，读者仍能知道具体任务和约束吗？

## 1.2 国内外研究现状

### 写作任务与范围

主体是已有研究的进展、路线、机制比较及证据边界，回答“别人解决了什么、怎样解决、在什么条件下成立、还需要了解什么”。1.1解释价值，2.1说明拟研究工作，2.3说明实施与验证；自己的投影头、损失选择、实施风险、实验控制和项目状态通常属于后两者，不能挤占综述。与课题的关系可以简短收束，但不必每段都转到“本课题拟”。有依据的进展应直接介绍，不能把全文写成风险提示。

方法论文的Introduction通常为特定贡献建立动机，Related Work定位其与近邻方法的区别；开题报告还需交代课题各方向的共同背景及选择依据。借鉴论证动作，不照搬贡献列表、宣传表达、历史研究空白或单篇论文的狭窄选文范围。没有独立Related Work时，可定位Introduction、方法背景和讨论中的相关论述。

| 用户当前任务 | 执行动作与交付边界 |
| --- | --- |
| 先学习 | 分开总结领域内容与写法；记录实际版本、阅读位置、具体段落组的作用与衔接，区分原文组织和归纳建议；提交总结后停止，不自动改正文。 |
| 规划 | 理解题目、意义、研究内容和方案后，确定分类主轴、必要/简述/排除范围；给逐段中心问题、比较维度、来源需求和衔接，不替用户确定候选机制。 |
| 撰写或修改 | 先核对相邻章节职责与可用证据，再完成授权正文；已有方案可说明关注的问题，但不能反过来成为前人不足的证据。 |
| 诊断 | 用小节与短句定位，说明问题类型、影响和依据；给保留/补充/压缩/移位/删除建议，同时指出原稿有效内容。不把组织偏好判成事实错误。 |

先复用已核实材料；不要求每次精读固定数量论文，不重复核验未变化的来源。发现会改变判断的证据缺口再定向查原文。新建完整报告遵循[选文和文字确认](topic-to-plan.md#新建完整报告的默认流程)，其他普通阶段切换不额外要求确认。案例仅在需要示范写法时读取：[研究现状写法案例](research-status-cases.md)。

### 精读范例并迁移

先读与本题相关的完整章节及相邻上下文，再选能解释写法的连续段落，记录实际版本与章节或页码。分别辨认本段要让读者理解的判断、各句的事实/比较/原因/限定作用、引用支持位置，以及下一段为什么接在这里。比较范例如何从已有进展引出问题、从信息需求引出设计；不要只复述论文研究内容，也不要求每篇都有独立研究现状或局限章。

将有用的组织动作适配到用户材料：先说明已有方法或基线做什么，再解释拟改变的信息、约束、权重或处理层级及其作用假设；按共同问题组织文献，保留实际成立条件。用户方案是研究主线，不是前人存在缺陷的证据。学到的写法只决定如何解释已有材料，不提供新的事实、成果或未经核查的创新定位；开题中的拟开展工作不套论文的已完成语气。

写后反向概括各段的中心判断，核对相邻句段是否真的存在原因、比较、证据或递进关系。关系缺失时从已给材料补解释或重排，不仅替换连接词。遇到内部汇报或反复辩解，先取出其中的事实、必要条件和真实不确定性，直接写研究内容；无信息的重复才删除，不用禁词表或空洞保证替代。分析通常留在工作上下文，不生成额外台账或塞入正式正文；交付时仅简要说明借鉴位置、采用的组织方法和仍需材料。

### 1.2.1 概述

先交代研究对象、核心问题与后文路线图，再解释理解比较所必需的输入输出、任务边界和概念。不是教材概念表，也不应以本项目的数据划分流程取代领域概览。

分类前区分研究任务、监督来源、学习范式、表示机制、模型组件和评价设置。若拟列标题不在同一层级，先解释其依赖或交叉关系，再确定主次。优先以研究问题为主轴，在路线内部按机制或发展过程组织；只有时间演进确实解释了问题变化时才以年代为主轴。不机械按论文、国籍、年份或拟开展工作数量分组，不为迎合候选方法倒推分类。

### 1.2.2 研究现状

**选文与深度。** 区分用于学习组织的写法范例、解释起点的奠基工作、直接相关方法和补足判断的证据来源；同一论文可兼任。按相关性和论证需求选取，不以期刊等级或最低篇数替代判断。直接路线应讲清进展、机制差异、证据条件；背景路线讲到能理解后文即可，不能因某模型知名就展开成百科。研究路线数量不必等于工作项数量。

**比较与综合。** 先找共同问题和比较维度，再选择文献支撑。可用简短内部表组织“工作/任务条件/监督与输入/机制/证据/边界”，不强制生成独立台账。可比较监督信息、训练与推理输入、知识传递对象、组件作用、数据条件、计算代价等；按题目选择，不要求全部列齐。先承认各路线解决的部分，再讨论有依据的限制；不是每篇论文都必须有缺点。

只有用户提供的文献摘录时，以其材料编号和段落定位支撑判断，明确只依据已读摘录；没有作者或题录就不补造正式文献编号。先提取共同任务、机制和成立条件，再写连续正文；材料未报告某项指标不等于该方法没有这种能力。支持关系可在正文外简短说明，不用反复的风险提示打断正文。

**段落规划。** 每段围绕一个中心判断，按需记录以下信息；这是规划槽位，不是正文固定句式：

| 中心问题或判断 | 支撑文献与位置 | 比较或解释动作 | 与前后段衔接 | 缺证据时处理 |
| --- | --- | --- | --- | --- |
| 本段让读者理解什么进展或差异 | 原文事实、作者评价或已标明的综合依据 | 比较共同维度，或解释一条路线如何发展 | 为什么此处需要这一段，下一段进一步回答什么 | 定向补证、收窄断言、暂留明确缺口或删去非必要论断 |

路线整体可按“问题与进展 → 代表机制及差异 → 证据条件 → 尚待回答的问题”推进，但不机械套到每段。相邻论文共同支持一个论点时综合讨论，不逐篇复述摘要。机制讲到读者能够理解差异与适用条件为止，自己的完整公式和工程实现放入2.3。修改混合段落时，按句子或分句判断功能：保留有依据的前人进展、适用条件及必要的课题定位；压缩重复说明；将具体实施与验证安排移至对应章节，不因出现“本课题”便整段移位。移位后连同相邻段落检查：中心判断是否仍成立，依据是否足够，前后能否衔接。若只剩模型简介，应具体指出缺少哪项进展、哪两个对象在什么维度上的比较，或哪一层关系的解释；已有证据足够时重组，缺证据时标明所需来源，不用本课题假设补齐。判断与依据已经完整时，不强制扩写。

**证据强度。** 分开处理原论文事实、作者评价、跨论文归纳和本课题假设。作者对其他方法的评价应保留其任务条件；历史版本中的“尚缺研究”须核对当前适用性。“未读到”或“未明确报告”不是“没有人做”；尚未建立的研究缺口写为待核查问题，不将推断伪装成共识。来源保留实际版本和章节/页码，不能把预印本阅读位置标成正式版。有限范围检索不支持全面查新结论。

**补充材料与冲突。** 新材料与已有结论不一致时，先区分任务、数据、指标、测量条件及版本是否相同。条件不同则分别陈述，不平均数值或选有利结果；条件看似相同但原因不明时保留分歧，只收窄受影响结论并指出需核对的具体字段。不能仅因来源较新便认定它取代旧结论，未经验证的解释不得写成冲突原因。

**局部修改的移位边界。** 需要移出方案细节但未授权修改目标章节时，只改当前章节，并在正文外逐项保留“待移入内容及建议位置”，不能直接改其他章节，也不能把移位当删除。保留原有引用、参数、限定条件及拟定状态；无依据的结论另列为删除或收窄，不混入待移内容。已授权同时修改目标章节时才实际移入，并检查原处衔接与目标处重复。合理段落不作无关改写；格式整理不扩大为内容修订。

**按缺口修复。** 事实没有来源时，明确需要核对的主张和证据，补证或收窄；事实已有但只逐篇介绍时，围绕共同问题重组并写出有来源的联系、差异或取舍，不默认追加论文；比较已有但衔接中断时，补足任务、条件或作用层级的关系，不用“因此本课题拟”掩盖推理缺步；仅措辞不清时局部改写，保留原有事实和引用。几类问题可以并存，优先修复影响结论的部分。证据足够时应直接写清已有进展，不以待补说明或风险提示替代正文。

原稿中的“应该比较机制、条件和效果”等写作指导不是研究现状。材料足够时，用实际对象和机制写出互补、替代或条件适配关系；材料只说明机制时，就完成机制比较，不必等待性能数字才写正文。关键句同时谈机制、效果和泛化时，分别核对各分句的支持来源；题录真实或描述了机制，不代表它能支持整句效果判断。

图表：路线分类图或维度一致的比较表可选，不将不同数据集的数字直接排名。引用贴近被支持的主张，不借一篇综述证明所有细节。

验收：读者能否围绕共同问题，复述主要进展、路线间的联系或差异，以及支持这些判断的依据，而不只是列出模型或逐篇摘要？比较表仅是组织手段，不能替代正文对关系的解释。机制与适用条件的比较应说明差异，不要求所有研究采用相同协议；性能优劣及收益归因则须有可比条件与匹配证据，不从异质结果直接排名。单篇机制介绍可以服务于相邻段落的综合，不要求每段都比较多篇。事实和作者评价是否有匹配来源？自己的方案是否挤占综述，移位后论证是否完整？收束的问题是否有依据且不固化未定方案？只检查本次相关内容，不以段数、引文数或“每段都有缺点”判合格。

### 1.2.3 发展趋势

综合前文多项研究反映的变化方向及仍受限制的能力，再简短引出课题关注的问题，不逐篇重复模型。趋势须有跨工作依据并保留适用范围，单篇未来工作只能作为该作者的建议；候选机会不称确定未来。自己的实施先后、负结果预案属于研究方案或计划，评价应当更严格等规范性建议也不自动构成已发生的领域趋势。不得把所有热点列成拟做内容。

### 计算病理专用提醒（仅相关题目使用）

图像基础模型是表征来源，视觉语言学习涉及监督来源与学习范式，蒸馏研究知识传递，原型是表示或约束形式，切片聚合连接图块与WSI，迁移评价检验能力；先解释关系，不将它们当同层级模型清单。图文预训练不直接证明文本辅助蒸馏有效，聚合改进不直接证明编码器改进，多个损失或训练头不构成多教师。这些提醒不规定模型、数据规模、损失或工作项数量；非医学课题不套用这些对象。

## 2.1 研究目标及研究内容

开头用一段说清总体目标与研究范围，然后分数据/评价和工作项。

### 2.1.1 数据集和评价指标

按“为何选此数据 → 对象与单位 → 标签与划分 → 处理流程 → 指标定义与适用边界”写。需要来源、访问状况、授权、样本单位、标签、评价协议；未知数量留待补，不自动沿用范文数字。

医学数据保留患者/病例分组；视频或时序按任务防止相邻片段泄漏。指标区分主指标、辅助指标及单位/方向；给公式必须解释变量、聚合方式和任务条件。效率比较需相同硬件、输入、批大小等条件，不把FLOPs直接等同实测延迟。

图表可用数据组成/划分表与处理流程图，不放虚构结果。非数据驱动课题改为研究对象、材料或验证方法，先检查模板允许。

### 2.1.2 主要研究内容

每项写：要解决的子问题、拟采取的思路、具体研究活动、与总目标关系。目标是想回答什么，内容是做什么，方法是怎么做，不能互换。

推荐结构：“针对[限定条件下的问题]，拟研究[具体机制]，通过[工作内容]，考察[可评价的性质]。”方括号为写作槽位，不原样进入正式稿。

与2.2/2.3/第3部分按名称一一对应；不是每项都必须另起一篇论文。相互独立的模块应说明共同目标，否则建议缩小范围。

## 2.2 拟解决的关键问题及难点

逐项回答：难在哪里、为什么难、已有方法在本题条件下能解决什么、还有哪一项需要处理或验证。没有相关证据时，不强迫写成“已有方法无法解决”；系统研究也可以研究已知机制在给定业务约束下如何实现与检验，而不虚构算法空白。

按“条件/矛盾 → 失败机制 → 实现或验证障碍 → 要突破的点”写。材料来自文献、预实验或设计分析，假设性机制须明确。

不要把“搭建网络”“训练模型”本身当科学难点；也不要把这一章写成完整2.3。完成后读者应理解方案设计的必要性。

## 2.3 拟采用的研究方案

对每个工作项：设计动机 → 输入输出与总体流程 → 关键机制 → 训练/求解或实施步骤 → 验证设计 → 可行性与风险。可以一幅总路线图加必要模块图，不为凑图重复画。

每个图框在正文中有解释。数据驱动方法明确训练与推理使用哪些信息，未知测试标签不能参与训练或调参；性能对照保持数据划分和评价条件可比，消融只变待验证因素。系统研究则说明状态、接口、正常及故障路径，在约定工作负载下检查功能正确性和资源开销，不套用训练/推理或标签划分；其他方法按实际求解过程选择验证方式。

### 本地材料与正式正文的边界

本地材料是理解课题的输入，不自动成为正式报告内容。未完成实验、内部日志、排错记录、脚本或配置清单、资产盘点和助手进度说明默认不写入正文，也不作为可行性已成立的依据。已有预实验或资源基础仅在用户明确要求纳入、且材料足以支持相应状态时写入匹配章节，说明必要的数据、协议及结论范围；“用户提供过”或“旧稿已写过”不等于已批准纳入。不把获准纳入的初步结果升级为独立复现或正式验证。

用户明确排除本地或未完成工作时，连同对应历史结果、数量、表格、图内“已有基础”声明及内部来源说明一起处理，不能从参考文献移到正文继续保留。按内容性质取舍：内部工作状态删除；支撑研究动机的历史结果移除后，以已有文献和待验证问题修复论证；独立成立且符合用户研究方向的方法保留为拟采用方案。不能把已有结果数字改成预期指标，不能仅将“本项目已实现”替换为“本课题拟实现”而照搬所有配置，也不能将未公开设计伪归给论文。资源条件未确定时保留必要前提，不假称具备。

判断句子作用而非禁用词：“本课题拟研究……”可以正常表达研究定位；“本项目已有……”若只是夹带未获准的本地状态则应移除。研究方案本来就包含作者拟开展的工作，不要求每句都是论文结论；已有研究依据、作者假设与未来验证必须区分。清理范围覆盖获准修改的正文、表格、题注和图内文字，并同步处理编号、交叉引用及删减造成的衔接缺口；超出授权的关联位置列为待处理，不擅自改动，也不读取更多私有材料来补回用户要求排除的内容。

方法已经列出但论证仍空时，按[题目到方案](topic-to-plan.md)的“论证与可行性补强”补清基线作用、新增机制和资源前提，再展开必要公式。仅凭接口能接通不证明所需材料能取得；涉及辅助记录时先交代内容、配对单位与质量条件。

验收：外部读者能顺着步骤理解输入如何变成输出、哪一项验证检验哪一个设计吗？

### 把验证写到能判断结果

把本题核心问题写成“在什么条件下，相对什么对照，观察什么，怎样据此作判断”。若原稿只有“比较准确率、效率”等指标清单，补足以下缺失关系即可，不另造完整实验协议：

- **问题与对照。** 区分要证明的是机制作用、任务达标还是资源收益；对照应能回答该问题。保留用户指定的原始对照，但它若不满足业务要求，不能把“优于该对照”当作达标；需要时提出匹配要求的候选对照，不擅自改原目标。
- **观测与口径。** 说明指标的统计对象、起止点及必须一致的条件。验证时可见的参考真值，不自动成为算法运行时可用的信息；代理指标只支持对应层面的结论，例如采样次数不能单独证明整机节能。
- **结果与解释。** 用已给门槛或明确待确认的准则，写出什么结果支持预期、什么结果说明不达标或只能部分成立；不杜撰误差容限、提升比例或显著性。多个目标发生取舍时分别判断，不以一个指标改善抵消硬性约束失败。缺少某类数据时，相应结论保持待验证。
- **归因与优先级。** 关键对照要解释排除什么因素，如额外数据、计算预算或其他组件变化。不能隔离时，只评价组合方案并限定归因；核心比较优先，条件性扩展不挤占它。实现正确、优化目标下降和任务收益分开观察；一次无提升或统计不显著不自动证明机制无效，也不自动启动更多实验来追求正结果。

这些关系可在方案正文中用几句交代。不要为每个工作项机械增加消融、统计检验或实验表；收到真实结果后按同一判断口径更新解释，不能为迁就结果事后改目标，也不能从未达标结果推断所有场景都无效。

## 创新点、技术路线和可行性的位置

- 创新点：以“研究必要性 → 具体区别 → 可检验作用 → 匹配的验证”表述，在2.1.2提出、2.3展开、第3部分收束。必要性不要求每条前人路线都有缺陷；组合已有模块只能称拟改进方案，贡献大小待查新和验证；不为系统或非组件型方法强加消融。
- 技术路线：是步骤依赖及信息流，不是软件名清单，通常在2.3表达。
- 可行性：文献支持、真实资源、已有基础、风险和替代研究路径，与研究结果分开。默认置于2.3；学校模板明确要求独立章才拆出。

## 3.预期达到的目标

按各工作项写拟形成的方法、实验结论范围和可交付物。性能/效率是待评价目标而不是已达成数字。具体阈值只有协议或用户明确给定才使用，否则提出候选标准且说明待定。论文发表、专利授权、临床部署不能保证。

不重复详细网络结构；强调什么产物或证据意味着完成。允许实验否定假设，不能只定义“必须优于全部基线”。

## 4.论文工作计划

每阶段有时间、工作、交付、前置依赖。方法研究可按文献/范围 → 材料/基线 → 方法 → 相关验证 → 分析与论文 → 修改答辩推进；系统研究可将中间阶段改为需求与接口 → 原型 → 功能/故障/资源测试，不硬套训练与消融。可并行但应说明依赖；有截止日则倒排，日期未知用相对阶段。

不套范文年份。过去工作仅有事实才用“已完成”；研究阶段不应在交稿之后还必需未完成，发现日期重叠先区分合理并行和矛盾。

## 5.主要参考文献

真实来源、条目完整、文内文末一一对应、同一文献不重复编号。格式按当前要求统一；参考范文混合格式不具有标准权威。数据集/模型/指标来源各自核验，不用无关引用垫数。

### 正式发表身份与实际引用版本

全文获取渠道与发表身份分开判断。选用或修订预印本题录时，先查出版商、正式论文集或会议官方记录，并与官方预印本记录交叉确认；复用已核实且未变化的证据，不重复全面检索。题名可能改变，须结合作者、研究内容及版本关联确认同一论文，核对正式题名、渠道、年份、卷期、页码或文章号、DOI等实际存在的字段。

已有正式发表记录且正式版支持当前论断时，优先按正式论文著录，不能因本地PDF来自arXiv就继续默认预印本身份。区分主会与工作坊、录用与正式出版、在线发表年与卷期年；不能只换刊名而不核对版本内容。仅有录用证据不补造卷页和DOI；未找到正式记录只说明本次未核实到，不能断言尚未发表。未能核实正式身份时保留准确的预印本题录，并在交付说明中披露。

论断依赖预印本独有内容时，不借正式题录掩盖版本差异：核实正式版能否支持后再替换，必要时保留真实版本依据，并解释其用途。同一论文不因下载渠道不同重复列项；确需引用不同版本时说明各自支持内容。检索过程、下载说明和例行“勿混用版本”等提醒不写进正式题录。

### 题录准入与项目证据安置

本地非论文材料不作编号文献引用，也不列入参考文献表；包括本地工作文档、未发表项目资料及下述实现与记录。判断依据是材料性质而非保存位置：下载到本地的真实论文仍可引用，并按已核实的发表身份著录；不得为凑来源把本地文件编成题录。

内部代码、脚本、配置、实验日志、项目记录和助手工作说明不作为学术文献条目，不用添加类型标识将其包装成可引用论文。是否保留相关正文，先按2.3“本地材料与正式正文的边界”判断；只有明确允许纳入的项目结果才保留简洁来源说明。用户已排除本地内容时，不得改挂“来源：本项目实验记录”绕过要求。不编造作者、日期、公开地址，也不把历史记录称为独立复现。

用户要求参考文献仅收录论文时，网站、模型卡、代码仓库和内部资料均不纳入编号文献表。存在支持同一论断的真实论文才可改引论文；否则按正文准入规则保留获准内容的就近来源说明或指出证据缺口，不能用数据集介绍论文替代用户样本数量、划分和结果的依据。这是用户的收录范围，不泛化成“所有非论文来源均不合法”；其他任务明确需要的标准、专著、公开数据或软件来源按实际要求另行判断。

移出不合格题录时，先查明它支持的全部正文、表格和题注，按正文准入规则决定删除、修复论证或保留获准内容的来源说明，再清理对应引文；不得只删文末条目留下悬空编号，也不得为保住编号换成无关论文。按授权范围同步调整来源映射、首次出现顺序及文内文末对应；未授权正文或文献表修改时只给处理建议，不擅自执行。

局部修改沿用原稿已有引用标识及对应来源；新附件内部的[1]等只在该附件内有意义，不能直接占用报告中的同号引用。新增来源未纳入报告文献表时先用可追溯的临时材料标识，正文外说明对应位置。只有在授权范围覆盖相关正文和文献表时才统一编号并同步核对；不能为修一段而重编号未授权章节。未见到完整文献表时，不宣称全文引用已核验。

引文贴近实际支持的分句，不用段末一组引用掩盖不同来源的支持范围。论文、实现、数据网页和项目记录可承担不同证据职责，不能因为名称相近就合并；网页介绍不证明项目实际使用的版本、规模或结果。格式选择、来源身份及重编号方法见[格式指南的参考文献与正文引文](format-rules.md#参考文献与正文引文)。

## 避免章节重复的检查

1.1说明为什么值得做；1.2综合已有进展、路线差异和有依据的未解问题；2.1说明要做哪些事；2.2解释难在哪里；2.3解释怎么做和怎么检验；第3部分定义预期产物；第4部分说明何时完成。相同内容出现两次时应改变职责，不能只换同义词。

## 根据反馈继续修改

先读当前稿和反馈所指位置，包括用户已经手动修改的版本。将意见转成“原句问题 → 本次修改动作 → 修改后读者应能回答的问题”；据原文能判断时直接处理，不要求用户重新填写需求表。笼统的“不够好”先定位最影响本次任务的具体缺口，不能默认全文重写。可按以下方式理解常见反馈，不能仅凭反馈标签判原稿有错：

| 反馈 | 核对原稿后采取的动作 | 不能用什么替代 |
| --- | --- | --- |
| 像论文流水账 | 找出已有材料能支持的共同问题和机制关系，重组相关段落，保留有用事实与引用 | 只加“此外、然而”等连接词，或机械增加论文数 |
| 创新不突出 | 分清已有进展、课题的条件差异及拟验证的问题；证据足够才表述具体拟贡献 | 加热门模块、贬低前人、把未查新写成首次 |
| 方案太空 | 按题目到方案“论证与可行性补强”补清问题依据、相对基线的增量、资源前提及验证归因 | 用模块、参数、公式或连续风险提示替代机制解释 |
| 太啰嗦、不像正式稿 | 压缩重复、移出协作说明，保留改变结论的条件、数值口径与拟定状态 | 删除不确定性后，把计划包装成已完成成果 |

反馈中的措辞愿望不构成研究事实。意见与证据或既定范围冲突时，完成可以成立的修改，在正文外简短解释未采纳部分及原因；只在确需改变课题目标或关键选择时询问。若问题牵涉未授权章节，指出冲突位置及后续动作，不悄悄同步改写。

候选选择以用户最新明确意图为准，旧稿或历史建议不自动成为定案；已实现和结果状态仍须材料支持。核对本次授权范围内正文、公式适用范围、图注、表格及计划的候选状态：未落实资源的扩展应有启动前提，计划不能把待选方案写成必用方案。相关图表或章节未授权时只指出不一致和建议位置，不越界同步修改。

交付按本次授权给替换段落或另存新版，不仅列建议。核对反馈涉及的问题是否在正文中得到解决、保留项是否完整、相关上下文是否连贯；文件修改还应核对未授权部分。检查通过即停止，不强制每节确认或无限润色。只要求诊断时仍只给定位与建议。

## 成稿的读者检查

完成本次授权正文后，用成稿中能定位的句子回答：读者知道要解决什么具体问题吗？研究现状说明了已有路线之间哪一种联系或取舍，依据在哪里？方案中的验证能回答哪个问题？只检查所写章节适用的问题；若答案仍需依靠对话中的未写信息，补好该处连接或明确关键缺口，不因此重写全文，也不另开固定多轮流程。

区分研究限定与写作过程说明。任务条件、暂定参数、拟开展状态和证据边界留在正文；“本轮未检索全文”“不编造实验结果”等助手工作说明放在正文外，不让它们替代机制解释。无证据支持的断言应收窄或删除，不能只移走免责声明而留下过强结论。正文先交付，必要的来源对应、待补或修改说明随后简短列出；只有诊断请求才以问题清单为主。

## 从空泛到具体的写法对照

以下是虚构教学例子，只示范论证动作，不作为任何真实课题的事实或通用方法。

| 位置 | 不充分的写法 | 如何改成具体写法 |
| --- | --- | --- |
| 研究意义 | 深度学习发展迅速，本课题意义重大。 | 先说明任务和约束：若目标设备有明确资源预算，本课题拟研究该预算下的分割精度与推理开销取舍；设备限制需用户材料支持。 |
| 研究现状收束 | 现有方法都存在不足，因此提出新网络。 | 指出待核实的比较维度：应核查相关工作是否在相同输入和设备条件下比较融合机制；证据不足时，将此列为综述核查问题，不断言所有前人都未研究。 |
| 关键问题 | 设计模型并完成训练。 | 解释具体矛盾：降低融合计算量可能影响细节保留，拟通过控制融合尺度与通道数分别考察其作用；这里是待验证假设，不是已观察到的结果。 |
| 预期目标 | 准确率提升10%，发表高水平论文。 | 形成同协议对照、资源开销测量和误差分析，明确候选方法的适用条件；没有依据时不预设提升数值或发表结果。 |
