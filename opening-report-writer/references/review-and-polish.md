# 审查完善、术语规范化与反馈返修

本文件定义开题报告全生命周期中的**阶段三（审查完善、术语符号规范化与反馈返修）**。本阶段与阶段一（[拆题与选文规划](topic-to-plan.md)）、阶段二（[章节起草与生成](section-writing-guide.md)）、阶段四（[图表与 Word 格式交付](format-rules.md)）解耦，完整承载草稿生成后的事实与协议锚点保护、论证修复、跨章节术语与数学符号规范化、去套话润色、草稿诊断及导师反馈返修。

## 三种审查触发模式

- **模式 A（起草后伴随自检）：** 完成阶段二初稿生成后，在正式交付前按本文件六道工序在模型内部完成锚点、术语与语体自检，直接先输出**正式正文**，随后在正文外简短附上必要的来源对应或待补清单（保持与新建/起草章节习惯完全兼容，不额外增加多轮形式化确认卡点）。
- **模式 B（专项审查与改写）：** 当用户针对已有草稿要求执行“术语规范化”“去套话润色”“局部改写”或“单条反馈修改”时，直接跳过阶段一（选文/拆题）与阶段二（从零起草），按对应工序执行；为充分发挥自回归模型“上文约束下文”的注意力机制、避免核对表沦为写完后的“事后补票”，直接交付修订稿时统一采用 **`Audit → Rewrite → Verify` 三段式输出结构**（若用户明确要求先确认锚点或术语表再改写，则只输出第一段并等待确认）：
  1. **第一段（前置锁定｜《正文外：前置锁定锚点与术语基准》，控制在 5–10 行以内）：** 在生成修订正文之前，先在回复顶部显式列出从原稿提取的**四类固定锚点**（核心论点、数值与统计口径、必要限定条件与评价协议、引文编号 `[n]` 映射）及**本次锁定的标准术语/缩写/数学符号基准**，以此直接约束随后的正文生成；
  2. **第二段（核心交付｜《修订后正文》）：** 独立区块输出干净、可直接复制进报告的正式正文（绝不把核对表、免责套话或修改汇报混入正文段落内部）；
  3. **第三段（末尾核销｜《正文外：改写锚点核销与术语符号统一对照表》）：** 在正文后简短输出《改写锚点核销结果》（确认四类锚点零丢失及已清理的套话/过度断言词）与《术语与符号统一对照表》（及必要的待补/待移清单）。
- **模式 C（全文/章节深度诊断与统稿）：** 按工序一至工序六由重到轻（先保事实锚点与协议 → 再修论证与去重 → 再统术语与符号 → 再精修语体标点 → 最后核图文引文与定稿门禁）系统排查；仅要求诊断时输出“原句定位 → 问题类型 → 修改动作与保留锚点”，不修改文件；获准统稿时按模式 B 的 **`Audit → Rewrite → Verify` 三段式输出结构**交付。

## <a id="改写锚点与核对"></a>工序一：改写锚点锁定与事实/协议保真审查

1. **四类固定锚点提取（动笔前必做）：** 局部改写、去套话润色、压缩或重组段落前，先从原稿识别并锁定四类不可改动的固定锚点：
   - **① 核心论点与推导方向：** 每段回答的中心判断、因果/对比关系及本课题研究定位；
   - **② 数值与统计口径：** 样本规模、划分比例、超参数、损失权重、实测均值/方差/百分比等；严禁将“效果较好”“误报有所缓解”等定性描述脑补为具体数值（如虚构“降低了36.67%”），严禁凭记忆凑整或替换为常见默认值；
   - **③ 必要限定条件与评价协议：** 任务前提、样本单位、既定多折 vs 单折评价协议、最终评估样本信息不参与选模/调参/特征维度选择的防泄漏边界、离线特征缓存与训练分支的视图一致性、多因素同时变化时的综合效应归因边界，以及“拟开展”的未完成状态；
   - **④ 引文编号与来源映射：** 原有 `[n]` 或临时材料标识、所支撑的具体分句范围及已核实的正式发表版本身份，严禁把本课题自设配置或未核实推论挂在原论文引文编号下。
2. **本地材料清理与跨章移位保护：** 按[本地材料与正式正文的边界](section-writing-guide.md#本地材料与正式正文的边界)排查并清理未获准纳入的内部日志、脚本、资产清单或伪装成题录的本地文件；需将越界细节（如1.2中提前展开的本课题具体参数、层间配对编号或实验组代号）移往其他章节但未获目标章节修改授权时，在正文外完整列出“待移入文本 + 建议目标位置”，绝不把移位当成删除。
3. **前置锁定与正文后《改写锚点核销结果》标准格式：** 在模式 B/C 中，动笔前先在《正文外：前置锁定锚点与术语基准》小节简短列出四类锚点与标准术语基准（5–10 行以内）；独立输出《修订后正文》后，在《正文外：改写锚点核销与术语符号统一对照表》小节中逐条核销（绝不混入正式正文、图表或 DOCX 文件内部）：
   - 【核心论点】：已保留原段关于……的中心判断，未改变推导方向；
   - 【数值与口径】：已原样保留……（列出具体数值/样本量/参数），无定性转定量或凑整；
   - 【限定与协议】：已保留……限定条件与评价协议前提（原括号内必要限定已拆解融入主句）；
   - 【引文映射】：已保留 `[n]` 对应原支撑分句，无增删或错位；
   - 【清理项】：已删去……（列出删去的空洞套话、报幕词、过度断言词、过程汇报或免责短句）。

## <a id="避免章节重复的检查"></a><a id="根据反馈继续修改"></a>工序二：论证链条、章节去重与反馈返修审查

### 避免章节重复的检查

1.1说明为什么值得做；1.2综合已有进展、路线差异和有依据的未解问题；2.1说明要做哪些事；2.2解释难在哪里；2.3解释怎么做和怎么检验；第3部分定义预期产物；第4部分说明何时完成。相同内容出现两次时应改变职责，不能只换同义词。

### 根据反馈继续修改

先读当前稿和反馈所指位置，包括用户已经手动修改的版本。将意见转成“原句问题 → 本次修改动作 → 修改后读者应能回答的问题”；据原文能判断时直接处理，不要求用户重新填写需求表。笼统的“不够好”先定位最影响本次任务的具体缺口，不能默认全文重写。当反馈指出“太空、不落地、论证或可行性不足”时，联动[题目到方案的论证与可行性补强](topic-to-plan.md#论证与可行性补强)，逐一排查“现象直接跳到方案、有公式无机制增量、有配置无关键资源落实、有指标无归因对照”四类论证缺口。可按以下方式理解常见反馈，不能仅凭反馈标签判原稿有错：

| 反馈 | 核对原稿后采取的动作 | 不能用什么替代 |
| --- | --- | --- |
| 像论文流水账 | 找出已有材料能支持的共同问题和机制关系，重组相关段落，保留有用事实与引用 | 只加“此外、然而”等连接词，或机械增加论文数 |
| 创新不突出 | 分清已有进展、课题的条件差异及拟验证的问题；证据足够才表述具体拟贡献 | 加热门模块、贬低前人、把未查新写成首次 |
| 方案太空 | 按题目到方案“论证与可行性补强”补清问题依据、相对基线的增量、资源前提及验证归因 | 用模块、参数、公式或连续风险提示替代机制解释 |
| 太啰嗦、不像正式稿 | 压缩重复、移出协作说明，保留改变结论的条件、数值口径与拟定状态 | 删除不确定性后，把计划包装成已完成成果 |

反馈中的措辞愿望不构成研究事实。意见与证据或既定范围冲突时，完成可以成立的修改，在正文外简短解释未采纳部分及原因；只在确需改变课题目标或关键选择时询问。若问题牵涉未授权章节，指出冲突位置及后续动作，不悄悄同步改写。将“根据审阅意见，我们已修改……”等修改过程汇报留在正文外；解释评价协议为何成立、对照比较为何有效、结论适用于什么条件的内容属于有效论证，应保留在正文中。含有事实、引用、必要条件与空泛辩解的混合句，只删除无贡献部分，保留有效信息并修复衔接。

候选选择以用户最新明确意图为准，旧稿或历史建议不自动成为定案；已实现和结果状态仍须材料支持。核对本次授权范围内正文、公式适用范围、图注、表格及计划的候选状态：未落实资源的扩展应有启动前提，计划不能把待选方案写成必用方案。相关图表或章节未授权时只指出不一致和建议位置，不越界同步修改。

交付按本次授权给替换段落或另存新版，不仅列建议。核对反馈涉及的问题是否在正文中得到解决、保留项是否完整、相关上下文是否连贯；文件修改还应核对未授权部分。检查通过即停止，不强制每节确认或无限润色。只要求诊断时仍只给定位与建议。

## <a id="术语与符号规范化"></a>工序三：全文术语、命名与数学符号规范化

单节润色或跨章节统稿时，逐项排查并统一以下四类术语与符号问题：

- **① 工作项与模块名称跨章/跨图表唯一（一物一名）：** 通查摘要/概述、1.1、1.2收束句、2.1.2主要研究内容、2.2关键难点、2.3各子节、第3部分预期目标、第4部分工作计划，以及**总体技术路线图、模块机制图框、表格表头与行名**。同一工作项、功能模块、网络分支、损失函数、数据集、对比基线或评价指标在全文必须使用**唯一标准名称**，彻底消除“前文叫 A、后文叫 B、图框里叫 C”的同物异名漂移。
- **② 中英文术语与首见缩写闭环：** 外文术语、模型或指标缩写遵循“**首见界定、后文一致**”——正文首次出现时采用“规范中文名称（English Full Name, ABBR）”界定（如“指数移动平均（Exponential Moving Average, EMA）”；对于 ResNet、Transformer、LoRA、mIoU 等本领域公认直接用英文的专有名词，首见交代清楚后保持统一），后文统一使用选定简称；集中清理“首见未界定直接抛生僻缩写”“后文反复多次用括号重注同一全称”“全称、中文简称与英文缩写无规律混用”三类问题。
- **③ 非标黑话与口语转本学科标准术语：** 将口语行话（如“打标签、跑消融、拿来做 baseline、拉齐特征”）、公文/商业黑话（如“赋能、抓手、闭环生态、组合拳、痛点”）及非技术比喻词（如“卡脖子”）统一替换为本学科规范学术术语（如“样本标注、开展消融实验、作为对比基线、特征对齐、关键技术瓶颈”）。严格区分**领域标准技术术语**与非标黑话：如可解释性中的“黑盒模型”、蒸馏中的“教师—学生网络”、病理中的“全切片图像（WSI）”属规范术语，直接使用、**不加双引号**，也不误当作黑话强改。
- **④ 数学符号、变量定义与上下标全局对齐：** 排查并消除**一符多义**（禁止同一字母如 `N`、`α`、`k` 在不同小节代表不同变量且无上下标区分，如用 `N_pat` 与 `N_patch` 区分患者数与图块数）；核对 2.1.1 指标公式、2.3 分步公式、总目标函数及模块图中的变量符号、上下标、集合/张量维度标注（如 `R^{B×C×H×W}`）是否完全连续对应，消灭未定义先使用、定义了不使用或前后符号漂移（如前文写 `L_G` 或 `L_align`、总式写 `L_base` 或 `L_match`）。
- **与阶段一基准表联动：** 若规划阶段已建立[核心术语与符号基准约定](topic-to-plan.md#核心术语与符号基准约定)，直接以该表为唯一准绳通查全文；若对已有草稿半途统稿，则先在第一段前置锁定全局标准名再执行替换。

**改前 → 改后微缩示范（修复同物异名 + 重复括注全称 + 符号一符多义与漂移）：**
- **改前：** `2.1.2 节对 N=1,200 例样本采用跨尺度特征对齐模块与指数移动平均（Exponential Moving Average, EMA）；2.3.1 节在单切片 N=512 个图块上通过多尺度融合支路（图2-1中称层次对齐单元）再次引入指数移动平均（Exponential Moving Average, EMA）计算 L_align，总损失为 L_total = L_cls + λL_match。`
- **改后：** `2.1.2 节针对 N_pat=1,200 例患者样本构建跨尺度特征对齐模块，并采用指数移动平均（Exponential Moving Average, EMA）更新教师参数；2.3.1 节在单切片 N_patch=512 个图块设置下，由跨尺度特征对齐模块（与图2-1同名模块对应）利用 EMA 教师特征计算对齐损失 L_align，构成总目标函数 L_total = L_cls + λL_align。`

**正文外《术语与符号统一对照表》标准格式：** 执行术语规范化或统稿交付时，按 `Audit → Rewrite → Verify` 三段式在正文后的第三段附上简短对照表：

| 类别（工作项/模块/术语/缩写/符号） | 原稿不一致或非标表述 | 统一后标准表述 | 涉及章节/图表位置 |
| --- | --- | --- | --- |
| 示例：核心模块名 | 多尺度融合支路 / 层次对齐单元 | 跨尺度特征对齐模块 | 2.1.2、2.3.1、图2-1 |

## <a id="语体句式与标点精修"></a>工序四：学术语体、句群结构与标点精修

本工序与[题目到方案的论证贡献标准](topic-to-plan.md#段落表达)及[格式指南的标点边界](format-rules.md#正文中双引号与小括号的学术边界)严格对齐：

- **词汇与句子去留（按论证贡献判断，不用死板禁词表）：** 清理纯规避争议的免责套话、由规则原话直接泄漏的防御性短句（如“不承诺提升幅度或发表成果”“接口可连接不代表资源已具备”“不以前项取得正收益为前提”）、修改过程说明（如“根据审阅意见，我们已修改……”）及密集二元否定短句（“是 A 而非 B；二者并非同一问题”）。排查自我夸耀词（“详尽、全面、深入、深刻剖析、全方位”等示例）与空洞报幕词（“具体如下、显而易见、不难发现、正如前文所述”等示例）：无具体维度支撑时落实为具体比较维度、变量关系与适用条件或删去；保留承载实质意义的名词性术语（如“控制系统、系统综述”中的“系统”）及紧跟实质结论的“综上所述”。
- **实证与预期动词匹配证据强度（防过度断言，保留合理学术限定）：** 动词强度必须严格匹配证据性质与开题阶段边界。引述已有文献或获准纳入的预实验结果时，使用 `表明、显示、在……设置下改善了/降低了、高于/低于对比基线`，严禁将有限样本下的经验改善拔高为 `证明了（prove）、彻底解决了、完美克服了、全方位超越、实现了绝对纯粹的……`；阐述本课题拟开展方案与预期目标时，使用 `拟构建、拟探究、验证……在……条件下是否能够降低/提升、考察……的权衡关系`，同时**保留**有证据依据的学术谨慎限定（如 `提示、可能与……有关、在当前划分协议与样本规模下`），不得为追求语气武断而删去合理限定。
- **段落标题与反机械八股（保护真并列对象）：** 学校模板要求的编号层级优先；**研究内容、实验组设置、评价指标、协议步骤、创新点等真并列对象**允许采用统一模板和序数列项以保证清晰对照；仅对**论述性段落**（背景推导、文献评述、难点机理分析）破除机械对称切分（不在每个一/二级标题下强行固定拆两个三级标题或凑三点式），论述段避免机械序数与“小标题+冒号+排比句”八股清单，使相邻自然段按各自论证职责（因果推进、转折对比、问题—机制—验证）呈现有差异的句群结构、起句角度与自然长短层次。
- **双引号与小括号边界：** 双引号仅用于直接引语、首次界定的特定专有命名，以及被提及的词、标签值、字段名、问卷题项（清理给普通动词、形容词或常见词滥加的引号）；小括号仅用于缩写界定、单位与量纲、公式图表编号、取值范围、符号定义、分组代号及必要文献/条款注记，**除 `式（2-3）`、`（1）` 等编号自带括号外，同一自然句内注释性小括号不超过 1 处**（可作同位语的简短代号如“实验组 G2”直接融入主句）；原括号内确属冗余解释才删，涉及适用范围、前提假设或比较基准的限定条件必须保留并拆解融入主句。

**改前 → 改后微缩示范（清理夸耀/黑话 + 实证动词降级 + 控单句括号并保留必要限定）：**
- **改前：** `本课题对轻量化分割网络进行了深入剖析，具体如下：通过引入通道重加权作为抓手赋能特征提取（即对不同通道乘以可学习系数）（实验组 G2）（仅在边缘设备显存不高于 4 GB 且采用 INT8 量化时成立），证明了本方法彻底解决了病灶边界模糊的“卡脖子”痛点。`
- **改后：** `针对边缘设备显存不高于 4 GB 且采用 INT8 量化的部署条件，本课题在实验组 G2 中引入通道重加权机制，拟验证其是否能够在受限通道容量下改善细粒度病灶边界的分割精度。`

## <a id="成稿的读者检查"></a><a id="从空泛到具体的写法对照"></a>工序六：成稿的读者检查与交付门禁

### 成稿的读者检查

完成本次授权正文后，用成稿中能定位的句子回答：读者知道要解决什么具体问题吗？研究现状说明了已有路线之间哪一种联系或取舍，依据在哪里？方案中的验证能回答哪个问题？分步公式与总目标函数的符号是否完全连续对应？配图是否紧随对应子节正文且图内标签简洁？只检查所写章节适用的问题；若答案仍需依靠对话中的未写信息，补好该处连接或明确关键缺口，不因此重写全文，也不另开固定多轮流程。

区分研究限定、正文学术语态与写作过程说明。任务条件、暂定参数、拟开展状态和证据边界用自然、正面的学术语言留在正文；“本轮未检索全文”“不编造实验结果”等助手工作说明放在正文外，同时排查并清理正文中由规则文本直接泄漏的免责套话（如“不承诺提升幅度或发表成果”“接口可连接不代表资源已具备”“不以前项取得正收益为前提”）及高频堆砌的二元否定短句。在此基础上逐项核查：

- **锚点与事实防伪：** 四类改写锚点（核心论点、数值口径、限定条件与评价协议、引文映射）完整保留，无“定性转定量”数字脑补、无虚构题录或张冠李戴、无脑补未提供的企业/对象细节；缺失材料处已按[格式指南的占位符格式](format-rules.md#缺口占位符格式)（`【待补：<数据/文献/基本情况之一>｜具体缺什么】`）显式占位并在正文外附待补清单，Word 草稿高亮，定稿交付前逐项清零。
- **术语与符号一致：** 全文工作项、模块、数据集与指标实现“一物一名”，中英文缩写符合“首见界定、后文一致”，口语/商业黑话已替换为本学科标准术语，数学变量与上下标无一符多义或前后漂移。
- **词汇、动词强度与语体：** 对照[题目到方案的论证贡献标准](topic-to-plan.md#段落表达)，常见空洞词按是否承载信息判断去留，不用死板禁词表；名词性术语（如“系统”）和紧跟实质结论的“综上所述”保留，无具体维度的空泛夸耀词或报幕词已落实为具体比较维度、变量关系与适用条件或删去；实证与预期动词严格匹配证据强度，已清理“证明了/彻底解决”等过度断言并保留合理学术限定。
- **段落、标题与标点：** 学校模板要求的编号层级优先，真并列对象允许统一模板和序数列项，论述性段落避免机械序数与“小标题+冒号+排比句”八股清单；双引号与小括号符合[格式指南的标点边界](format-rules.md#正文中双引号与小括号的学术边界)，除编号自带括号外同一自然句内注释性小括号不超过 1 处，原括号内必要限定条件已拆解融入主句。

**交付呈现顺序铁律：** 无证据支持的断言应收窄或删除，不能只移走免责声明而留下过强结论。**模式 A（起草阶段伴随自检）** 先交付正式正文，随后在正文外附上必要的来源说明或《待补清单》；**模式 B / 模式 C（专项审查改写与统稿）** 采用 `Audit → Rewrite → Verify` 三段式：先输出简短的《前置锁定锚点与术语基准》（5–10行），再独立输出干净的《修订后正文》，最后在正文外附上《改写锚点核销与术语符号统一对照表》（及必要的待补/待移清单）；仅诊断请求或用户明确要求先确认锚点/术语表时，才只输出清单。

以下是虚构教学例子，只示范论证动作，不作为任何真实课题的事实或通用方法。注意将示范正文与写作边界区分开，不要把括号内的规则说明抄入正式报告。

| 位置 | 不充分的写法 | 如何改成具体写法（正面学术表述示范） |
| --- | --- | --- |
| 研究意义 | 深度学习发展迅速，本课题意义重大。 | 针对边缘端部署场景下的计算与显存预算约束，本课题拟重点考察轻量化网络在分割边界精度与推理时延之间的权衡关系。（注：具体设备预算需有用户材料支持） |
