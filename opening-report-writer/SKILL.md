# 开题报告写作与格式

默认中文。支持主动筛选高匹配度参考论文，精读相关章节并学习其段落职责、句间关系、比较维度、机制解释与证据安排，围绕本课题重新组织正文；不复制他人个人信息、学校身份、原句或研究结果，不将用户自设配置挂在原论文引文名下、不把单篇局限泛化为领域通病，也不在研究现状中把本课题方案写成已有文献流派。参考材料可由用户提供，也可通过可用的合法渠道主动检索，不依赖固定本机目录；没有范文仍可开展题目分析和写作。精确模板复刻需取得原文件，不假称查看过。本 Skill 不附带开题报告、学校模板、论文全文或用户项目材料。

## 先确定本次交付

从当前请求与已有材料识别题目、对象/任务、模板、证据、修改范围及产物。复用已知的专业、学位、数据、方法、成果和期限，不从范文推断身份，也不要求填完整问卷。非阻塞缺口标注后继续；只有会实质影响课题或交付的缺失选择才集中询问。

只有题目且未指定产物时默认规划；明确要求草稿时完成可成立的授权章节，候选设计保持拟定状态，依赖未给事实的部分按[格式指南的占位符格式](references/format-rules.md#缺口占位符格式)标注待补。只学习、诊断或规划时不改报告；在对话中起草不自动授权写文件。新建完整报告默认按[题目到方案的完整报告流程](references/topic-to-plan.md#新建完整报告的默认流程)先询问并筛选参考论文，确认学习对象后精读与起草，文字确认后再配图。用户明确委托自行选文、明确授权连续完成图文或指定其他流程时，遵循相应授权，不重复确认；单纯“写完整报告”不自动跳过两个确认点。在获准的当前阶段完成各章节，不逐章等待批准。局部修改、诊断、排版和仅规划不强制重走此流程。

完整报告未给篇幅时，按正文约10,000字作软预算，不因默认预算删减指定内容或凑字数；明确要求优先，局部任务不套全文字数。具体适用范围及询问时机见[题目到方案](references/topic-to-plan.md)第6节。

## 按任务读取与交付

| 本次任务 | 读取范围 | 应交付的内容 |
| --- | --- | --- |
| 新建完整报告 | 题目到方案“新建完整报告的默认流程”；章节写法“精读范例并迁移”及实际章节 | 先交选文建议供确认，再交无图文字稿，文字确认后按需配图和整理文件；不把确认学习对象当作研究方案获批 |
| 拆题、提纲、方案规划 | [题目到方案](references/topic-to-plan.md)；[章节写法](references/section-writing-guide.md)对应章节 | 具体对象与约束、逐节要点、工作项—方法—验证对应；按影响列下一步最少材料及用途，通常不超过三项 |
| 学习范文或论文写法 | 章节写法1.2；涉及版式时读[格式指南](references/format-rules.md)“从参考材料学习” | 原文位置、组织动作、共性/差异和迁移边界，区分观察与建议；不自动改正文 |
| 研究现状规划 | 章节写法1.2 | 分类主轴、段落中心问题、共同维度、所需证据与衔接 |
| 起草章节正文（生成阶段） | [章节写法](references/section-writing-guide.md)对应小节及第5节“正文主张与多篇引用”；首次组织全文再读[题目到方案](references/topic-to-plan.md)，交付前按[审查与完善](references/review-and-polish.md#成稿的读者检查)伴随自检 | 授权范围内的连续正文与引用；过程说明、待移内容及待补清单放正文外 |
| 审查完善、术语规范化或去套话改写（审查阶段） | [审查与完善](references/review-and-polish.md)（工序一至工序六，不重走选文与拆题） | 按 Audit→Rewrite→Verify 三段式交付：正文前先列简短《前置锁定锚点与术语基准》，再交独立《修订后正文》，正文后附《改写锚点核销与术语符号统一对照表》，不篡改事实锚点与研究方案 |
| 诊断草稿 | [审查与完善](references/review-and-polish.md)；涉及章节职责时对照章节写法对应小节 | 定位原句，区分事实错误、证据不足、术语漂移、结构问题与表达偏好；说明保留锚点与修改动作，不改文件 |
| 参考文献格式统一或引用修补 | 章节写法第5节；格式指南“参考文献与正文引文” | 分开交付支持关系核查与格式修正结果；有依据的多篇合引可保留，编号组合不改变来源集合，不借机重写研究方案 |
| Word生成或仅排版 | 格式指南；需改内容时再读对应章节 | 可用工具支持的DOCX、格式依据和真实检查范围；仅排版不改研究内容 |

用户指定范文整理文末参考文献时，按格式指南“按指定范文整理文末题录”比较两份文件并实际修改；“无明显排版错误”不等于“已符合指定范文”。局部格式任务不重建整份报告，不套用默认对齐、缩进或统一删 DOI。

根据导师意见或用户反馈返修时，读[审查与完善](references/review-and-polish.md)“根据反馈继续修改”及“改写锚点锁定”；指出“太空、不落地、论证或可行性不足”时，先用题目到方案的“论证与可行性补强”定位缺口，再读受影响章节。涉及文献选用、引用核查或增删移动时，还读章节写法第5节，核实正式发表身份与题录准入；下载自arXiv不等于按预印本著录，内部代码与记录不列入学术参考文献。涉及引文排版或全文重编号时，再读格式指南“参考文献与正文引文”。需要句子取舍或多份材料组织成连续正文的示范时，读[研究现状写法案例](references/research-status-cases.md)，其中虚构材料不能作学术证据。真实论文学习需读实际原文并给位置。只处理一节不重做全文调研，也不强制读取全部参考文件。

## 组织与成稿

规划或写作时先明确“现实问题 → 已有进展及边界 → 研究问题 → 工作项 → 方法与验证 → 预期交付”。工作项在相关章节中用同一名称对应，数量由课题决定；题目过宽给收敛建议，不擅自换题。

学校当前正式要求与用户明确要求优先。没有指定结构时用[题目到方案](references/topic-to-plan.md#默认正文骨架)中的默认五部分骨架；参考指南编号仅表示默认职责，不能覆盖实际模板，不自动新增独立目录、创新点或可行性一级章。学校模板要求的编号层级优先；未规定时子节数量由课题逻辑体量决定，研究内容、实验组、指标、协议步骤、创新点等真并列对象允许统一模板和序数列项，仅对论述性段落破除机械对称切分（见[章节写法2.1.2](references/section-writing-guide.md#212-主要研究内容)）。

- **章节推进与范例迁移：** 先依据材料形成判断，再按章节职责写连贯段落；撰写摘要/概述、1.1与1.2时可按[精读范例并迁移](references/section-writing-guide.md#精读范例并迁移)学习对标论文的段落推进、比较维度与证据安排并围绕本课题重组，不在第一章提前展开第二章的具体参数或实验组代号。
- **改写锚点与术语符号统一：** 润色、压缩或统稿前先按[改写锚点锁定](references/review-and-polish.md#改写锚点与核对)保护核心论点、数值口径、限定条件/评价协议与引文映射，并按[术语与符号规范化](references/review-and-polish.md#术语与符号规范化)统一跨章/跨图表工作项与模块名称（一物一名）、首见缩写界定、学科标准术语及数学符号上下标。
- **论证贡献与语体边界：** 对齐[题目到方案的论证贡献标准](references/topic-to-plan.md#段落表达)与[语体句式精修](references/review-and-polish.md#语体句式与标点精修)，删去无信息贡献的免责套话、修改过程汇报及空洞夸耀/报幕词（词例仅作示例，按是否承载信息判断，不用禁词表；实证与预期动词匹配证据强度，不用“证明了、彻底解决、全方位超越”等过度断言词，保留改变结论范围的条件限定、协议理由、合理学术限定、名词性“系统”等术语及紧跟实质结论的“综上所述”）。
- **句式与标点边界：** 论述段避免机械序数与同构排比，双引号与小括号遵循[格式指南的标点边界](references/format-rules.md#正文中双引号与小括号的学术边界)及[成稿的读者检查](references/review-and-polish.md#成稿的读者检查)。
- **局部修改与待移安置：** 局部修改保留成立内容，不为每篇文献制造缺点；需移出细节但未授权目标章节时，在正文外完整保留待移文本与建议位置，不直接改其他章节。

## 事实与计划

逐句检查正文是否提供事实、条件、机制、比较、证据、推导或验证判断。若某句唯一作用是预先规避争议，删除后不影响中心论点、适用条件和证据关系，则删除；会改变结论适用范围的限定必须保留，并嵌入相邻论证。

- 区分“用户材料中的事实”“待外部核验主张”“推断”“拟开展方案”“缺失信息”。正文涉及本地工作、预实验或案例基本情况时，按[本地材料与正式正文的边界](references/section-writing-guide.md#本地材料与正式正文的边界)判断准入与保真：已获准纳入的数值、协议与真实背景保持一致，严禁将定性描述脑补为具体数值或编造未提供的企业/对象细节；前期基础详略按章节职责、证据需要与用户要求决定，不挤占拟开展方案。
- 范文是写法证据，不是科学正确性的证据。不能把范文数据、模型效果、课题来源、获奖发表或导师意见写成用户的。
- 拟贡献需说明有依据的研究必要性、相对已有工作的具体差异和可验证作用；必要性也可来自待检验的适用条件或现实约束，不强造领域空白。工作项数量与组织结构由课题决定（如按条件差异、约束递进、处理层级，或“基础底座→核心增量→迁移评价”等可选方式），不编造未经验证的模块依赖或伪因果。未经查新不称首次，未实验不称已提升。不要以模块名组合替代研究问题。
- 保留已有数据划分、种子、标签层级、实验协议和结论限定。核算实验运行次数，把“选择哪个模型/配置”与“使用多少折评估”分开：核对最终评估样本的信息是否参与模型、超参数、维度或方案选择，允许事前固定方案或在外层训练数据内部完成选择；不得以单一代表折默认替代既定多折协议，单折探索须有授权并与正式评价区分，不自动增加未授权的嵌套验证。核对离线缓存与训练输入的视图一致性，如实界定多因素对照的归因范围。医学/WSI 任务区分患者、切片、patch，不把切片标签当实例真值，不把算法指标写成临床获益；非医学题目不强加医学流程。
- 学术事实、数据、参考文献与基本情况在需要时查原始来源。严禁捏造作者、标题、期刊、年份、DOI 或数字引用，不把本课题自设配置或未核实推论挂在原文献引文名下，区分“已有文献已证实结论”与“本课题拟检验假设”；材料缺失时按[格式指南的占位符格式](references/format-rules.md#缺口占位符格式)（`【待补：<数据/文献/基本情况之一>｜具体缺什么】`，如 `【待补：数据｜样本量与划分比例】`）显式占位，并在正文外附待补清单。
- 签名、成绩、审批意见不得生成；未知身份留空。封面和审核表等只按实际模板或用户要求加入。

## 交付前

按[审查与完善](references/review-and-polish.md#成稿的读者检查)中的“成稿的读者检查”回看本次正文，核对四类改写锚点（核心论点、数值口径、限定条件与协议、引文映射）、跨章/跨图表术语与数学符号一致性、工作项覆盖、图表就近排版和时间可行性，清理混入正文或图内的规则套话与修改过程汇报。区分字符数与目标软件的实际字数统计口径，按用户或学校要求的统计范围实际统计；无法调用目标软件时将其他统计明确标为估计，不冒充Word实测。只修复当前问题，不强制输出检查表或无限润色。缺关键事实的全文称草稿，不把工作说明混入正文。

Word优先使用环境提供的documents工作流，否则用可用文档工具；本Skill不捆绑这些工具，也不要求安装其他学术Skill。有正式模板或同校母版DOCX时优先原位复用容器，完整保留封面、审批/选题/评议表合并单元格与固定说明、节属性及样式，仅清空样本个人信息并替换正文（定稿时核对封面是否遗留模板或旧稿的“初稿”标识），不从零重建简化表格。插图按实际文档可用宽度设定画布或计算缩放后的有效字号，以最终嵌入文档后的清晰度、换行、重叠与裁切作为验收依据，配色与同名可编辑源码同步交付遵循[格式指南的插图规范](references/format-rules.md#流程图配色与源码交付)，并检查两端对齐下长英文或符号组合是否拉裂词距。保留可编辑内容与已有模板，生成后从最终文件渲染并逐页查看。分别说明文字完成、文件生成、解析、渲染查看和实际软件打开；缺工具或失败就披露未完成步骤，不将文本冒充Word。区分正式要求、范文观察和暂定格式，不反复追问已给信息。
